# CSV import implementation review

Three independent GPT-6.1 Sol / High reviewers assessed the integrated implementation in parallel. All three finished before implementation fixes began. Review scopes covered backend correctness, feature security/resource controls, and frontend behavior/accessibility. This was a feature review, not a repository-wide security audit.

## Findings by category

| Category | Finding | Disposition and evidence |
| --- | --- | --- |
| Security/resource controls, P2 | Raw URI classification could disagree with Spring MVC for percent-encoded route aliases, bypassing early upload guards and standard multipart exclusion. | Fixed shared MVC-decoded route matching, all-unsafe-method CSRF guarding and whole-family/error-dispatch multipart exclusion. Independent static recheck approved; 12 targeted tests passed. Main boundary: [ImportUploadPolicy.java](../../../backend/src/main/java/com/campus/tracker/application/importing/ImportUploadPolicy.java); resolver: [ImportTransportConfiguration.java](../../../backend/src/main/java/com/campus/tracker/application/importing/ImportTransportConfiguration.java). |

Files: [useApplications.ts](../../../src/hooks/useApplications.ts), [ApplicationImportDialog.tsx](../../../src/components/ApplicationImportDialog.tsx). |

| Backend correctness | No confirmed P1/P2/P3 implementation defect. Independent recheck accepted the tests; all 18 lifecycle cases passed in the final 129-test backend suite. File: [ImportLifecycleTest.java](../../../backend/src/test/java/com/campus/tracker/application/importing/ImportLifecycleTest.java). |

The backend review found ownership/version checks, shared validation, atomic application/receipt transactions, canonical integrity, supersession, terminal-expiry locking, consistent quota snapshots and restricted grants aligned with the approved architecture. The security review found no additional concrete defect in those paths. The frontend review confirmed status-only automatic recovery, serialized writes, session guards, full-history refresh and literal-safe output boundaries.

Additional real-controller verification exposed Commons FileUpload retrying an underlying socket read after a timeout while finding the first multipart boundary. [ImportMultipartReader.java](../../../backend/src/main/java/com/campus/tracker/application/importing/ImportMultipartReader.java) now retains the first I/O failure and prevents further underlying reads. A deterministic test first reproduced two reads instead of one. The final real-socket test proves one failed read, same-owner capacity available at six seconds, terminal 408 below eight seconds and no servlet multipart access. The security reviewer independently approved this correction; no global connection/header timeout was changed.

The eight resolved [design review findings](2026-10-15-csv-import-design-review.md) remain requirements: 500-row receipt reservations, commit-coordinated terminal expiry, retained reservations, one aggregate quota snapshot, quota-safe correction supersession, malformed-response reconciliation, pre-body security/admission and bounded slow uploads. The implementation adjustments are recorded at the end of the [approved design](../specs/2026-10-15-csv-import-design.md).

## Verification and remaining limits

Final verification passed 68 frontend tests (including 12 React/JSDOM cases), the production build, 129 backend tests and two PostgreSQL 18.6 fresh/upgrade scenarios, with no failures or skips. The rebuilt bundled JAR passed real HTTP/restart checks, including native Node FormData through bundled serving and Vite, atomic rollback, duplicate receipts and discarded-response GET reconciliation. All three reviewers completed focused rechecks; all actionable findings are resolved. Commands, coverage and infrastructure limits are recorded in [VALIDATION.md](../../../VALIDATION.md).

Actual browser visual/reflow/theme checks, native modal keyboard containment and screen-reader behavior remain blocked by unavailable browser infrastructure. React/JSDOM focus assertions and Node FormData do not establish those properties. PostgreSQL 17 was not run; the available PostgreSQL 18.6 passed with Flyway's newer-version warning. No user database was changed, and no deployment was performed.
