## Selected job graph

- **verify / Application verification** (ubuntu-24.04): checkout one revision; Node22 and Temurin17; dependency caches; npm ci, npm test, npm run build; assert dist exists; Docker preflight; sh ./mvnw -B -ntp -Pwith-ui,postgres-it clean verify from backend; assert required JUnit/Failsafe reports include executed, unskipped PostgreSQL tests; npm run test:smoke with captured console transcript and pipefail. All UI/JAR/smoke inputs stay in the same job/checkout; no cross-run artifacts.
- **containers / Container builds** (ubuntu-24.04), parallel: checkout same revision; Docker/Compose preflight; compose config --quiet with distinct synthetic CI credentials; build migrate and app targets on the same daemon/BuildKit cache; inspect runtime users and Java17 runtime. No compose stack is started and no image is pushed.
- **required / CI required**: always runs after both jobs, succeeds only if both needs results are exactly success. Document this stable branch-protection check; do not change branch protection. Validate failure/cancel/skip/missing-result cases, not only success.

This avoids duplicate normal Maven test/verify runs and artifact handoffs. Source-image builds necessarily repeat unit verification because the existing Dockerfile treats tests as a build invariant; preserve that invariant. Both target builds reuse their shared backend stage so Docker does not repeat it per target.

## Triggers, bounds and trust

pull_request; push on main; workflow_dispatch. No path filters or privileged pull_request_target/workflow_run. Concurrency group keyed by workflow plus PR number/ref, cancel superseded runs. contents:read only, checkout persist-credentials:false, GitHub-hosted isolated runners, all actions pinned to verified full release commit SHAs. No OIDC/package/deployment writes. Explicit job timeouts. Cache downloaded npm/Maven dependencies only, keyed by lock/pom/wrapper; never cache dist or target. Failure diagnostics include only selected reports/transcripts with short retention, not env/database/dependency files. Smoke owns its temporary SMTP/JVM/Vite/H2 resources; hosted runner disposal bounds hard cancellation. Compose validation is not rollout or migration-gating proof.

## Runtime budget

Initial unmeasured hosted estimate: roughly 5–15 minutes wall time with parallel work jobs on normal network/cache conditions; cold pulls can be slower. Calibrate after the first hosted run. The observed Windows Java17 unit suite took 2:32 and is not a hosted baseline. Hard job/step timeouts remain the resource bounds.
